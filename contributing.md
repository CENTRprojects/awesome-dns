# Contribution Guidelines

Please note that this project is released with a [Contributor Code of Conduct](code-of-conduct.md). By participating in this project you agree to abide by its terms.

This list is curated and maintained by [CENTR](https://centr.org) on behalf of its R&D community. It is not a directory of every DNS tool available. The aim is a short list of tools that DNS operators, registries and researchers would genuinely recommend to each other.

---

## What we include

An entry must meet **all** of the following:

1. **DNS is the main purpose.** General web, SEO, email-marketing or "all-in-one domain toolkit" sites where DNS is one feature among many are out of scope.
2. **Open, or run in the public interest.** Either:
   - the software is published under an [OSI-approved open source licence](https://opensource.org/licenses), with a public source repository; or
   - it is a hosted service operated by a registry, research institute, standards body, non-profit or public authority (for example Internet.nl, DNSViz, Zonemaster).
3. **Established and maintained.** The project has a track record: a public history of commits or releases over at least six months, documentation, and some evidence of real-world use. New or single-commit projects are welcome to reapply once they mature.
4. **Adds something.** It is not a near-duplicate of a tool already listed, and the description says clearly what it does that existing entries do not.

## What we do not include

- Commercial or freemium hosted checkers, lookup sites, or SaaS products, including those with a free tier.
- Sites carrying advertising or whose main purpose is lead generation.
- Pull requests that remove, replace or reorder existing entries to promote another tool. If you believe an existing entry is broken or unmaintained, please open an issue instead.
- Bulk or automated submissions of the same tool to many lists.

## Self-submissions

You are welcome to submit a tool you build or work for, as long as you say so in the pull request and the tool meets the criteria above. Undisclosed affiliations will lead to the pull request being closed.

---

## Pull Request Guidelines

Please ensure your pull request adheres to the following guidelines:

- Use the pull request template and fill in every field, including licence and affiliation.
- Search previous suggestions to make sure your suggestion isn't a duplicate.
- Create individual pull requests for each suggestion.
- Use [title-casing](http://titlecapitalization.com) (AP style) in the following format: `[Tool Name](link) - Short description.`
- Use a plain hyphen (`-`) between the link and the description, matching existing entries.
- Include a licence badge and a maintenance badge (`Maintained: yes` or `Maintained: stalled`), and no other badges.
- Add the entry in alphabetical order in the relevant category.
- New categories or changes to the existing categorisation are welcome but should be explained in the pull request.
- Check your spelling and grammar, and make sure your editor removes trailing whitespace.
- The pull request and commit should have a useful title.

## How pull requests are reviewed

- CENTR reviews open pull requests periodically. Please allow a few weeks.
- Pull requests that clearly do not meet the criteria above will be closed with a short note pointing to this page.
- Borderline cases are referred to the CENTR R&D community before a decision is made.
- Entries already on the list are reviewed from time to time and may be marked as stalled or removed if they no longer meet the criteria or are no longer reachable.

## Updating your PR

If the maintainers notice anything that we'd like changed, we'll ask you to edit your PR before we merge it. There's no need to open a new PR, just edit the existing one.

If you're not sure how to do that, [here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md) on the different ways you can update your PR so that we can merge it.

Thank you for your suggestions!
